## 判断の経緯

初版 R3（G3, 2026-07-10）は「1.x 継続」だったが、下記により方針転換：

- **版体系の実態:** Kiota は CLI とランタイムを別系統でバージョニング。CLI（`Microsoft.OpenApi.Kiota`）は 1.34.1 が最新で 2.x 未リリース。ランタイム（Bundle/Abstractions）のみ 2.0.0 が最新 stable。よって本件は **CLI 据え置き＋ランタイムのみのバンプ**で、生成コードは再生成せず表面不変。
- **1.22.2 は 1.x 系の最終リリース**（保守終了）。今後の CVE 修正は 2.x にのみ入るため、セキュリティ保守上 2.x が唯一の前進線。
- 1.x 継続理由（①2.0 破壊的変更が不明／②G3 と回帰リスク分離）は両方解消。

## セキュリティ判定

**PASS**（High/Medium なし）。

### 検証済み（実地）
1. **CVE-2026-44503 / GHSA-7j59-v9qr-6fq9 修正の継承 = 確認済み。** advisory の脆弱範囲は `Abstractions < 1.22.0`、2.0.0 は範囲外＝修正済み。下限 `>= 1.22.0` を満たす。
2. `dotnet list package --vulnerable --include-transitive` を全プロジェクトで実行しクリーン。Bundle/Abstractions/Http/Serialization.* が一貫して 2.0.0 に解決（競合・ダウングレードなし）。
3. セキュリティ関連手書きコード（`WebhookSignatureValidator` 定数時間比較、`AllowedHostsValidator` 注入による許可外ホストへのトークン非送出、`RefreshingChannelAccessTokenProvider`）は API 互換・ビルド 0 警告・公開 API snapshot 差分ゼロにより挙動不変を機械的に確認。

### 指摘（Low・対応任意）
- **[Low] 下限が Abstractions のみ名指し** — RedirectHandler の実体は `Http.HttpClientLibrary`。Bundle が全サブパッケージを同版ロックステップ固定するため実害なし。→ CLAUDE.md 規約に補足を追記（Bundle 非経由の直接参照時のみ Http 側下限も明示）。
- **[Low] CLI 1.34.1 / ランタイム 2.0.0 の版系統分離** — `generate.ps1` の版照合ガードと R3 ロックステップ運用で許容範囲。
