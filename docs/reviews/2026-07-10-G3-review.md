## 指摘と対応

### 中: DI 二重登録が非冪等（コード）— **修正済み**
- 事象: `AddLineMessaging` を複数回呼ぶと名前付きクライアント `Line.Messaging` に Kiota 既定ハンドラ（Redirect/Retry 等）が毎回追記され多重化、`AddSingleton` も重複。
- 対応: 内部マーカー `LineMessagingMarker` で**ハンドラ差し込みを初回のみ**に限定、`MessagingClient` は `TryAddSingleton`。回帰テスト `AddLineMessaging_Is_Idempotent` を追加（2 回登録→`MessagingClient` 記述子 1 件・解決とルーティング維持）。
- 該当: `ServiceCollectionExtensions.cs`。

### 中〜低: シングルトン `MessagingClient` が単一 HttpClient を長期保持しハンドラローテーションが効かない（コード）— **受容（G4 で再検討）**
- 事象: シングルトンが構築時の `CreateClient` の HttpClient を寿命いっぱい保持し、`IHttpClientFactory` の `HandlerLifetime`（既定 2 分）ローテーションが適用されない（長時間プロセスで DNS 変更を拾わない古典問題）。ソケットプール共有の利益は得られる。
- 判断: PoC/一般的な Bot 常駐用途では実害小。**受容**とし、G4 で「都度 `CreateClient` する薄いラッパ or スコープ設計」を検討課題として残す。README/リリースノートで明記予定。

### 低: 高速パスの `_refreshAt` 非アトミック読み（コード＋セキュリティ両者一致）— **修正済み**
- 事象: `DateTimeOffset`（16 バイト）をロック外・非 Volatile で読み、torn read の理論的可能性。影響は「わずかに早い/遅い再発行」で漏洩・昇格には至らない。
- 対応: `_refreshAtTicks`（`long` = UtcTicks）へ変更し `Volatile.Read/Write` 化。期限を先・トークンを後に公開する順序で「新トークンを見たら新期限も見える」ことを担保。
- 該当: `RefreshingChannelAccessTokenProvider.cs`。

### 低: 更新型プロバイダの `IDisposable` が DI で破棄されない（コード）— **文書化で受容**
- 事象: ファクトリ内 `new` で `IAuthenticationProvider` として返るため、コンテナが `IDisposable`（`SemaphoreSlim`）を追跡しない。シングルトン寿命ではプロセス終了時に回収され実害小。
- 判断: 破棄責任を利用側ドキュメントに明記する方針で**受容**。

### 低: `refreshMargin ≥ 寿命` でキャッシュ無効化 → 毎回再発行（セキュリティ）— **受容（既定安全）**
- 事象: `refreshAt` が `issuedAt` にクランプされ以後毎回発行。発行 API への過剰リクエスト（自己 DoS）の可能性。既定マージン 5 分・通常の寿命（短期でも 15 分〜）では発生しない。
- 判断: 既定値では非発生。G4 で下限クランプ or 警告を検討課題として残す。

### nit: `FormUrlEncodedTests` の `async` に `await` なし — **修正済み**
- `Token_Request_Uses_FormUrlEncoded_ContentType` を非 async の同期テストへ変更。

## セキュリティ結論（明示要求 3 点）
- **タイミング攻撃:** 対策済み（`WebhookSignatureValidator` は `CryptographicOperations.FixedTimeEquals`、内容依存の早期 return なし）。
- **トークン漏洩:** なし（トークン/JWT/シークレットはログ・例外に出力せず、ハードコードもなし。JWT 署名鍵はライブラリ外＝`assertionFactory` 供給）。
- **ホスト誤送出:** なし（許可外は空トークン、AllowedHostsValidator は空集合＝全許可に決してならず既定へフォールバック、R1 の BaseUrl 順序も正しい、DI で CVE 修正版 RedirectHandler を差し込み多層防御）。
- 依存脆弱性: `dotnet list package --vulnerable --include-transitive` で該当なし。

## 推奨（人の go/no-go 用）
**GO を推奨**。高・中重大度のうち対応必須（DI 冪等性）は修正＋回帰テスト済み。両者一致の低指摘（`_refreshAt` アトミック性）も修正済み。残る受容項目（HttpClient ローテーション、IDisposable 破棄、refreshMargin 下限）は既定利用で実害が小さく、**G4 スコープ**として明示的に持ち越す前提であれば G4 へ進んで問題ない。
